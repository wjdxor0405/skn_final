# 리뷰 외부 소스 검토 — 유튜브 전사 · 유튜브 댓글 · 타 플랫폼 리뷰

**이 문서가 답하는 질문: 리뷰를 주는 공식 API가 없는 상황에서 팀이 후보로 낸 외부 소스 셋을
써도 되는가, 쓰면 우리 리뷰 신호에 들어가기는 하는가.** 2026-09-16 회의에서 "리뷰 기획 방향은
법적 리스크 검토를 포함해 다시 정한다"고 한 자리에 들고 갈 검토안이다. 법률 자문이 아니다 —
팀이 판단할 수 있게 층위를 나눈 것이고, 약관 조항은 회의 전에 원문을 확인한다(§7).
결정이 나면 `docs/decisions/0004` 로 남긴다.

`docs/decisions/0001~0003` · `docs/review_collector.md` 위에 선다.

---

## 0. 배경

- 2026-09-15 중간발표에서 멘토 셋이 같은 방향으로 말했다 — 리뷰는 근거의 한 축일 뿐 본질은
  추천이고, 막힌 소스를 애써 수집하지 말고 공식 API로 얻을 수 있는 데이터(언급량·트렌드)를
  검토하라. PC 부품은 공급업체가 적어 조작 리뷰의 유인도 크지 않다.
- 2026-09-16 회의에서 팀은 지금 리뷰 데이터가 공개 데이터셋 파생물이라 편향이 있을 수 있고,
  리뷰 본문을 주는 API는 찾지 못했다고 정리했다. 그 자리에서 나온 대안이 아래 셋이다.

| 후보 | 내용 |
| --- | --- |
| **B1** 유튜브 리뷰 영상 전사 | 리뷰 영상의 소리만 뽑아 로컬 STT로 전사하고, 제품 언급 구간을 텍스트+타임스탬프로 남긴다 |
| **B2** 유튜브 댓글 | 영상 댓글의 "써봤는데 별로더라"를 작성자 익명화 뒤 신호로 쓴다 |
| **B3** 타 플랫폼 리뷰 | 가격비교 사이트가 여러 쇼핑몰 리뷰를 모아 보여주듯 국내·해외 쇼핑몰 리뷰를 가져온다 |

## 1. 판단 틀

네 층위로 본다. 하나라도 "높음"이면 서비스 기능으로는 쓰지 않는다.

| 층위 | 무엇을 보나 |
| --- | --- |
| ① 플랫폼 약관 | 그 소스가 자동 수집·다운로드·저장을 허용하는가. API가 있으면 API 정책 |
| ② 저작권 | 리뷰·영상·댓글은 작성자의 저작물. 플랫폼에는 데이터베이스제작자 권리(저작권법 93조)가 따로 있다 |
| ③ 개인정보 | 공개된 계정명도 저장·프로파일링하면 개인정보 처리다 |
| ④ 부정경쟁 | 2022년 개정 부정경쟁방지법 — 상당한 투자로 축적한 데이터의 무단 취득·사용 |

여기에 우리 원칙 셋을 대입한다.

- **판정하지 않는다**(0001) — 리뷰가 가짜라거나 어떤 사람이 틀렸다고 말하지 않는다. 관측만 낸다
- **원문을 남기지 않고, 작성자는 소스별 솔트 해시로만**(0002·`review_collector.md`)
- **서버가 모르는 값은 화면에 내지 않는다**(0003)

그리고 리뷰 신호가 서는 조건을 기억한다. 관계·행동 축은 **누가 · 언제**로 서고, 같은 부류의
중앙값(7일 내 몰림 5.5%)과 비교한다. 이 조건이 안 서는 소스는 법을 다 통과해도 신호가 되지 않는다.

## 2. B1 — 유튜브 리뷰 영상 전사

| 층위 | 문제 | 무게 |
| --- | --- | --- |
| ① 약관 | 유튜브 서비스 약관은 서비스가 제공하는 방식 밖의 다운로드·복제를 금지한다. 소리만 뽑는 것도 다운로드다. Data API로는 남의 영상 자막을 내려받을 수 없고(소유자 인증 필요), 자동 생성 자막은 제공되지 않는다 | **높음** — 형사 문제가 아니라 계약 위반이지만, 서비스에 올리면 API 키·계정 정지 |
| ② 저작권 | 영상·음성·자막은 유튜버의 저작물이고 전사문은 복제물이다. 원문을 버리고 수치만 남겨도 전사 과정 자체가 복제다. 현행 저작권법에는 텍스트·데이터 마이닝 예외가 없다(개정 논의 중 — 확인). 공정이용은 연구에는 유리하나 서비스 기능에 얹으면 약해진다 | 중~높음 |
| ③ 개인정보 | 채널명은 공개 정보지만 저장·프로파일링하면 개인정보 처리. 0002 방식으로 낮출 수 있다 | 낮음 |
| 평판 | 회의에서 팀이 먼저 짚었다 — "유튜버는 좋다는데 우리가 별로라고 하면". 허위 여부 축(리뷰의 수치 주장과 스펙 대조)을 영상 단위로 돌리면 "이 유튜버가 틀렸다"가 되어 명예훼손·업무방해 소지 | 높음 |

**원칙 관점에서 더 앞서는 문제.** B1은 리뷰가 아니라 **한 사람의 후기**다(회의에서도 "한 명이고
많아야 두 명"). 관계·행동 축은 표본이 1이면 서지 않는다. 법을 다 통과해도 리뷰 신호에는 넣을
것이 없고, 남는 쓸모는 **견적 입력**(유튜브 견적을 그대로 따라 산 사용자의 구성을 검증·설명하는
기능)뿐이다.

**합법 경로.** 유튜브는 리뷰 소스가 아니라 견적 입력 소스로만 쓴다 — Data API `videos.list` 의
제목·설명란(허용된 읽기)에서 부품명과 링크를 뽑는다. 9/16 회의가 이미 이쪽으로 좁혔다. 음성
전사가 꼭 필요하면 **크리에이티브 커먼즈(CC BY)로 올라온 영상만**(API 응답의
`status.license = creativeCommon` 으로 걸러진다) 출처 표시와 함께 쓴다. 데모 소량이면 이것으로
충분하다.

## 3. B2 — 유튜브 댓글

| 층위 | 문제 | 무게 |
| --- | --- | --- |
| ① 약관 | `commentThreads.list` 는 허용된 읽기. 다만 API 데이터는 저장 기간 제한(30일 안에 갱신·삭제 — 원문 확인)과 집계·재가공 제한이 있다. 우리가 남기는 것은 해시·시각·요약뿐이라 "API 데이터 저장"에 해당하는지 해석 여지가 있다 | 중 |
| ② 저작권 | 댓글도 저작물(짧으면 창작성이 부정될 수 있다). 원문을 남기지 않으면 낮다 | 낮음 |
| ③ 개인정보 | 작성자 채널 ID → 소스별 솔트 해시. 0002 그대로 | 낮음 |

**원칙 관점에서 치명적인 문제 둘.**

1. **몰림 기준선이 깨진다.** 7일 내 몰림 지표는 리뷰가 서로 독립적으로 도착한다는 가정 위에
   선다. 댓글은 영상 공개 직후에 몰리는 것이 정상이라 모든 영상이 "몰림"으로 나온다.
2. **평점이 없고 대상이 불명확하다.** 영상 하나에 부품 여러 개가 나오면 댓글이 어느 제품
   얘기인지 알 수 없어 옵션 단위 `review_subject` 에 붙일 수 없다(`review_collector.md` §3).

법적으로 가능해도 **신호가 되지 않는다.** 쓰지 않는다.

## 4. B3 — 타 플랫폼 리뷰

| 층위 | 문제 | 무게 |
| --- | --- | --- |
| ① 약관 | 국내 쇼핑몰의 약관과 robots.txt 는 자동 수집을 금지한다. 해외 직구 플랫폼도 마찬가지 — "회색지대"가 아니라 명시적 금지다 | 높음 |
| ② 저작권 | 리뷰 원문은 작성자 저작물이고, 리뷰 모음은 플랫폼의 데이터베이스제작자 권리 대상이다. 원문을 안 남겨도 취득 행위가 문제다 | 높음 |
| ④ 부정경쟁 | 상당한 투자로 축적한 데이터의 무단 취득·사용은 부정경쟁행위. 국내 판례에서 숙박 플랫폼 크롤링은 형사 무죄였지만 손해배상은 인정됐고, 채용 플랫폼 건은 데이터베이스권 침해가 인정됐다 | **높음** — 핵심 |

**오해 하나.** 가격비교 사이트가 여러 쇼핑몰 리뷰를 보여주는 것은 **제휴·입점 계약에 근거한다.**
같은 화면을 크롤링으로 만드는 것과 법적 근거가 다르다.

## 5. 합법 경로 정리

| 경로 | 리뷰 본문 | 관계·행동 축(작성자·게시시각) | 서비스에 쓸 수 있나 |
| --- | --- | --- | --- |
| 쇼핑몰 공식 API(제휴·검색·오픈API) | **없음** — 상품·가격·링크만 | 없음 | 가격·링크에는 됨 |
| 공개 학술 리뷰 데이터셋(지금 데모) | 있음 | 있음 | **연구용 라이선스** — 데모까지. 실서비스 불가(라이선스 문구 확인) |
| 자체 수집(first-party, `origin='first_party'`) | 있음 | 있음 | 됨 — 유일하게 서비스로 이어지는 길 |
| 유튜브 Data API 제목·설명란 | 리뷰 아님 | 없음 | 견적 입력으로만 |
| 유튜브 CC BY 영상 전사 | 후기(n=1) | 없음 | 데모 예시·출처 표시 조건 |
| 공식 트렌드·언급량 API(포털 데이터랩류) | 리뷰 아님 | 없음 | 인기도 축으로 — 약관 안에서 쓸 수 있는 유일한 외부 신호 |

9/16 회의의 "리뷰를 주는 API는 없다"는 결론과 같다. 리뷰 본문이 있는 합법 소스는 학술
데이터(데모)와 자체 수집(서비스) 둘뿐이다.

## 6. 제안 — 회의 안건

1. **리뷰 신호 축은 지금 상태로 동결한다.** 공개 데이터셋 파생 관측, 판정 없음, 화면에는 관측
   문장만. 최종 발표 전에 새 소스를 수집하지 않는다. (멘토 "힘 빼라" · 팀 "잠깐 두자"와 같다)
2. **유튜브는 리뷰 소스가 아니라 견적 입력 소스다.** Data API 제목·설명란만 읽는다. 음성 전사·
   자막 다운로드는 하지 않는다. 예외는 CC BY 영상 + 출처 표시.
3. **댓글은 쓰지 않는다.** 법 이전에 신호가 안 된다 — 몰림 기준선·평점·대상 셋 다 없다.
4. **타 플랫폼 리뷰는 제휴 없이 수집하지 않는다.** 발표 문장은 이렇게 — "외부 플랫폼 리뷰는
   공식 API가 본문을 제공하지 않으므로, 리뷰 소스는 공개 학술 데이터(데모)와 자체 수집(서비스)이다."
5. **어느 소스든 화면 규칙은 넷으로 고정한다.** 원문 저장 안 함 · 작성자 해시 · 판정 문장 없음,
   그리고 새로 하나 — **유튜버·판매자 단위로 식별되는 부정 신호를 내지 않는다.** "이 견적은
   틀렸다"가 아니라 "이 구성은 파워 여유 8%".
6. 리뷰 축을 뺀 자리에는 **공식 트렌드·언급량 API**를 후보로 올린다. 리뷰가 아니라 인기도
   축이므로 근거 문장도 그렇게 쓴다("최근 3개월 검색량이 같은 부류 중앙값의 2배").

## 7. 회의 전 확인할 것

- 유튜브 API 개발자 정책 — 저장 데이터 30일 조항 원문, 집계·재가공 제한 조항, `captions`
  엔드포인트 범위, `status.license` 값
- 지금 데모 리뷰 데이터셋의 라이선스 문구 — 비상업·연구 한정 여부. 발표에서 "데모까지"라고
  말할 근거
- 저작권법 텍스트·데이터 마이닝 예외 개정 진행 상황
- 포털 데이터랩류 API 이용약관 — 상업 이용 범위, 표시 의무
