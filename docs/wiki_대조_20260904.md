## 2. 회의에서 정해졌는데 저장소에 없는 것

### 2-1. 라이선스 명시 (제출 전 필수, 비용 거의 없음)
"오픈소스(Odoo)를 썼다는 점을 솔직히 명시하고 라이선스를 밝히기로" 합의했다
(`(pc)2026-09-03_12`). 현재 저장소에 `LICENSE` 파일도, README의 라이선스 절도 없다.
Odoo는 LGPLv3(Community) 기준이므로 **어떤 판을 어떤 라이선스로 썼는지**와
이 저장소 자체의 라이선스를 한 절로 적는 것으로 족하다.

### 2-2. 이상 거래 탐지
`(pc)2026-09-03_09 AI 에이전트와 CRM 연결 전략 회의`에서 정리된 결론:

- 품목명 검사는 하되, 이름을 바꿔 등록하면 사전 차단은 불가능하다는 한계를 **인정하고**
- 최근 체결 이력 대비 **가격·수량 이상치**를 탐지해 차단하는 선까지 간다
- 그 이상(위법 판단)은 외부(경찰 등) 영역으로 넘긴다

코드에 흔적이 없다. 붙일 자리는 `negotiate.py`의 스크리닝(재고·사양·납기·MOQ가 이미
걸러지는 곳)과 낙찰 확정 직전 두 곳이다. 이력 비교 기준은 `deals` 테이블 또는 Odoo
발주 이력 중 하나를 골라야 한다 — **정하지 않은 채로 남아 있다.**

### 2-3. 오버레이형 보조 툴

비전 슬라이드용인지 회의록만으로는 갈리지 않는다 — **팀 확인 필요.**

### 2-4. AWS 배포 범위 축소

현황 문서 §4-2의 "AWS 실배포"를 이 범위로 좁혀 읽을 것.

## 5. 이 문서를 다시 만들 때

위키 DB를 직접 읽었다. `sqlite3` CLI가 없어 python 모듈로 **읽기 전용** 접속했다.

```bash
cd ~/wiki && python3 - <<'PY'
import sqlite3
db = sqlite3.connect("file:dev.db?mode=ro", uri=True)   # 반드시 mode=ro
c = db.cursor()
for r in c.execute("select title, updatedAt from Page order by updatedAt desc limit 20"):
    print(r)
PY
```

- 본문은 `Page.contentText`에 있다. 앞부분이 정리된 회의록이고 **뒤에 원문 전사가
  그대로 붙어 있다** — 전사 뒷부분은 품질이 낮아(반복·환각) 근거로 쓰지 말 것.
  앞 3000~4000자만 읽으면 결정 사항은 다 들어온다
- 녹음은 `Meeting`, 문서는 `Page`, 둘 다 `projectId='proj_skn'`
