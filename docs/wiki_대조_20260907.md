## 4. 아직 정해지지 않은 것 — 사람이 정해야 한다

### 4-1. 협상이 메인인가 (가장 큰 갈림길)

9/6 22시에 팀은 멘토에게 **"마켓플레이스 B2B 협상을 메인 테마로 유지"**한다고
설명했다. 그런데 같은 회의에서 멘토가 정리한 수렴 도식에는 **협상 노드가 없다.**

```
컨셉1 추천 시스템        ← 추천 근거 설명 / 멀티모달 취향 / 실패작 재추천 / 편향 파괴
컨셉2 합리적 구매 클린징  ← 적대적·광고성 리뷰 탐지 / 마감 임박 재고 진위 검증
```

게다가 후보 목록 검토에서 "흥정/가격 협상 에이전트"는 *"실제 협상은 내부 회의를
거쳐 나오는 복잡한 과정이라 재현이 어렵다"*는 평을 받았다.

- 협상이 살면 → `negotiate.py`·`agents.py`·`audit.py`·정보 비대칭이 전부 메인
- 협상이 죽으면 → 위 전부가 부가 기능으로 내려가고, 저장소의 절반이 새로 필요해진다

**멘토가 팀의 메인 테마를 기각한 것인지, 새로 올라온 별개 아이디어만 기각한 것인지가
회의록으로는 갈리지 않는다.** 확인 없이 코드를 건드리면 안 되는 자리다.

### 4-2. B2B인가 B2C인가

9/5 16시의 "상품페이지 없는 마켓플레이스"는 **B2C 제안**이었고 멘토도 "고객이 바이어
업체가 아니라 개인일 수도 있다"고 동의했다. 9/6 22시의 두 컨셉(추천·리뷰 어뷰징·마감
임박 핫딜)도 전부 B2C 쪽이다. 반면 이 저장소는 RFQ·발주서 기반 **B2B**다.

### 4-3. 해커톤 트랙 — 저장소 문서와 회의가 정면으로 어긋난다

| 출처 | 판단 |
|---|---|
| `docs/해커톤_요건_대조.md` §5 | Professional Agents가 **정확히 맞는다.** 주제문 *"routine and repetitive tasks in the background"*가 표준계약 자동 처리 분기 그대로 |
| `2026-09-05_16` | **트랙 미스매치.** 세 트랙 모두 "사람의 반복 업무 해결"을 요구하는데 B2B 기업 간 조달은 여기 안 맞는다 |

둘 다 맞을 수는 없다. §4-1·§4-2가 정해지면 자동으로 갈린다.

### 4-4. Strands — 저장소에 흔적이 없다

9/5 17시에 *"현재 코드가 베드락과 (전사상 '시아렘', STK 기반)을 거의 다 지원하도록
만들어져 있어 설정만 바꾸면 전환 가능하다"*는 발언이 있다. **이 저장소에는 없다** —
`app/llm_agents.py`는 OpenAI SDK를 직접 호출하고, 기본값 `rule`은 LLM을 아예 안 쓴다.

`docs/해커톤_요건_대조.md` §0은 이걸 **"심사 기준 1번 사실상 0점"**으로 적어 뒀다.
셋 중 하나다 — ①다른 브랜치에 있다 ②다른 팀원 작업물이다 ③전사 오인이다.
**확인이 먼저다.** (전사에서 고유명사가 깨진다는 건 9/4 대조 문서가 이미 겪었다.)

## 7. 이 문서를 다시 만들 때

위키 DB를 **읽기 전용**으로 직접 읽었다(`sqlite3` CLI가 없어 python 모듈 사용).
`~/wiki`는 로컬에서만 열린다 — 웹 주소는 외부에서 닿지 않는다.

```bash
cd ~/wiki && python3 - <<'PY'
import sqlite3
con = sqlite3.connect("file:dev.db?mode=ro", uri=True)   # 반드시 mode=ro
con.row_factory = sqlite3.Row
c = con.cursor()
# 날짜 페이지(최상위)와 그 자식 문서
for r in c.execute("""select id,title,updatedAt from Page
                      where projectId='proj_skn' and parentId is null
                      order by title desc limit 10"""):
    print(r['title'], r['id'])
    for k in c.execute('select title,length(contentText) n from Page where parentId=? order by "order"', (r['id'],)):
        print('   ', k['n'], k['title'])
PY
```

- 문서는 `Page`(본문 `contentText`), 녹음은 `Meeting`, 둘 다 `projectId='proj_skn'`
- **본문의 마지막 한 줄이 원문 전사 전체다**(3만~7만 바이트). 정리된 회의록은 그
  앞부분이고, 전사는 품질이 낮아(반복·환각) 근거로 쓰지 말 것.
  `[l for l in text.split('\n') if len(l.encode()) < 3000]` 로 잘라내면 요약만 남는다
- 개발용 `dev-local.db`에는 이 문서들이 없다. `dev.db`를 볼 것
- **제목이 아니라 `Page.id`로 인용할 것**(§1). 제목은 전사 품질에 좌우되고
  나중에 손으로 고쳐진다. id는 cuid라 안 바뀐다
