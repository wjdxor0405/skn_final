## 3. Strands 이식 — 무엇을 얼마나

**1단계 (요건 통과선)** — ✅ **완료** (`fcbb0cf`). `app/strands_agents.py` 를 새로
두고 `Agent(model=OpenAIModel(...))` + `agent.structured_output(pydantic)` 을 쓴다.
`SellerAgentPort`/`BuyerAgentPort` 덕에 `negotiate.py` 는 `_build_agents()` 분기 한
절만 늘었다. 프롬프트는 `app/agent_prompts.py` 로 빼서 두 어댑터가 공유한다 —
정보 은닉 규약이 프롬프트 문장 안에 있어서 어댑터마다 들고 있으면 조용히 깨진다.

**남은 확인 하나**: 모델 왕복을 아직 못 돌렸다(키 없음). 제출 전에 키를 넣고
`NEGOTIATOR_MODE=strands` 로 협상 한 건을 실제로 돌려 볼 것.

**2단계 (점수가 나는 곳)**: 기존 함수를 `@tool`로 노출해 에이전트가 직접 호출하게 한다 —
`feasibility.check()`, `intake.classify()`, `store.sellers_for()`. 심사 기준이
"non-trivial"을 요구하므로 어댑터만 바꾼 1단계로는 낮게 받는다.

**3단계 (가점)**: `OpenAIModel` → `BedrockModel`, AgentCore 배포, Strands 멀티
에이전트로 §4-1의 동시 디스패치 구현.

**남기는 것**: `agents.py` 룰 기반과 `audit.py` 감사자는 버리지 않는다. 에이전트를
감싸는 **가드레일**로 재배치하면 Design 점수에 유리하고, 데모 당일 API가 흔들려도
`rule` 모드로 같은 화면을 돌릴 수 있다.

**대가**: 새 의존성(지금은 `odoo_client.py`가 표준 라이브러리만 쓴다), Bedrock으로
가면 리전별 모델 액세스 승인 대기, 도구 호출로 라운드당 지연·비용 증가.

## 5. 트랙 선택과 서술

**Professional Agents** ("work productivity, repetitive judgment-heavy tasks")로 낸다.

대회 주제문이 *"handles routine and repetitive tasks in the background"* 인데,
표준계약 범위 내 발주를 협상 없이 자동 처리하고 **범위를 벗어날 때만** 에이전트가
붙는 분기가 이 문장 그대로다. Potential Impact에서 가장 강한 자산이므로 영상
첫 30초에 놓는다.
