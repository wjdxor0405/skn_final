## 2. P0의 경계 — LLM은 한 줄도 안 들어갑니다

rev.1에서는 "P0에 LLM이 조건 해석 1곳만 남는다"고 썼는데, 회의록을 보니 팀은 이미 **0곳**으로 정해뒀습니다. 근거가 세 군데서 일치합니다.

| 회의 | 발언 |
|---|---|
| 11시[40:42] | 화자3: MVP는 LLM을 사용하지 않는 룰 기반으로 구매부터 판매까지. 검증 절차는 전부 제외. **이것이 P0** |
| 12시[18:26~18:32] | 화자3: 조건 해석은 자연어를 포맷으로 바꿔주는 기능이고, **당장은 LLM을 빼도 된다** |
| 17시[47:02] | 화자1: **LLM을 쓰는 단계는 P1**이라서 무료 API 키 라운드로빈도 P1 |

그래서 P0의 세 항목은 이렇게 축소됩니다.

- **M-12 TAG 매칭** → Text-to-SQL이 아니라 조건 쿼리 룰. L0의 fuzzy match를 확장
- **A-02 퍼체이스** → 자연어 파싱이 아니라 입력 필드 형식 검증
- **R-03 리포트** → 템플릿 렌더링

**P1의 첫 세 항목**이 자동으로 정해집니다: ①조건 해석(자연어→포맷) ②협상 발화 ③리포트 요약 문단. rev.1 §3-1에서 제안했던 안 B는 여기 ③으로 들어갑니다.

**발표 리스크는 그대로 남습니다.** 9/15 데모에 LLM이 한 번도 안 돌면 기술 심사위원 2명 앞에서 "왜 에이전트인가"에 답할 근거가 화면에 없습니다. 대응은 둘 중 하나입니다.

1. **P1 일부를 9/15 전에 당긴다.** 비용이 가장 싼 건 리포트 요약(거래당 호출 1회). 그다음이 조건 해석.
2. **도식으로 답한다.** 15시 기획안 그림에 감사 검증·OKR 검증이 이미 들어가 있으니, 구현분과 계획분을 색으로 구분해 보여주고 "P0는 파이프라인 검증, P1이 LLM 투입"이라고 단계를 설명합니다.

한 가지 덧붙일 게 있습니다. 11시[14:49]의 할루시네이션 사례("재고 10대인데 100대 가능하다고 응답")는 **룰로도 걸러집니다.** 재고·납기 초과 주장을 코드로 제외하는 정도면 15시 기획안의 '감사적 검증' 자리를 P0에서 채울 수 있고, 데모에서 가장 잘 보이는 장면이기도 합니다. LLM 없이 P0에 넣을 수 있는 유일한 검증입니다.

## 3. P0 데모 시나리오 (11시 화자3 안 그대로)

```
1. 바이어가 구조화 양식 5필드로 RFQ 입력      → 빈칸·형식 검증만
2. 셀러 A·B·C 카탈로그는 사전 등록 상태
3. 룰 기반 조건 매칭 → 셀러별 O/X 판정
   └ 재고·납기 초과 주장은 여기서 제외        ← 감사 검증의 P0판
4. 통과한 셀러의 입찰 데이터 저장
5. 후보가 0곳이면 → 조건 수정 요청(사람 개입)
6. 수량 구간 할인 등 룰 기반 미세 조정
7. 최저가 1순위 추천 → 사람이 선택·승인
8. 로그 → 템플릿 리포트 생성 (폴더 + 화면)
```

**① 도메인이 두 갈래입니다.** 15시 기획안 예시는 GPU(20대·대당 210만원), 17시에서는 제조업체를 가정하고 서훈님과 데이터 컨셉을 잡기로 했습니다. 화면·데이터·발표가 전부 여기 걸려 있어 9/5 전에 하나로 정해야 합니다.

**② 챗봇의 위치.** 11시[55:30]에서 화자1이 "채팅과 리포트가 빠지면 SK는 주제가 없다"고 짚었습니다. 지금 P0에 챗봇이 없습니다. 알림 전용으로 붙였다 뗐다 할 수 있게 만들자는 안(11시[62:35])이 나와 있으니, 이걸 P0에 넣을지 P1으로 둘지 결정이 필요합니다. 발표에서는 챗봇 화면이 더 이해하기 쉽다는 의견도 있었습니다(11시[63:43]).

**③ AWS 범위.** EC2 1대 + Docker Compose로 4프로세스만 올리는 안(1~2일)을 기본으로 권합니다. VPC 3개·게이트웨이는 도식에 남기고 구현분과 색을 구분합니다. 멘토가 지적한 프록시·VPN 구성은 팀 전체가 이해하지 못한 상태라(11시[7:38~8:33]) 데모 범위 밖으로 두는 편이 안전합니다.
