## 1. 범위

- **본체 부품을 사는 사용자에게만** 만든다. 주변기기는 만들지 않는다(기획서 5.5).
- 새 PC 조립(`mode=build`)과 업그레이드(`mode=upgrade`) 둘 다. 업그레이드는 "분리 → 장착 → 확인"이 조립과 다르다.
- 리포트(`/plan/report/:id`)의 "조립·설치 가이드" 섹션. 인쇄·PDF도 이 섹션을 그대로 쓴다.
- **통합 리포트**(본체+주변기기, 기획서 4.3·UI-11)에서는 본체 슬롯 품목만 가이드에 넣고, 본체 품목이 하나도 없으면
  섹션을 통째로 뺀다. 판별은 `config/categories/computer.yaml` 의 `slot_structure` 로 한다(슬롯 이름 목록을 따로 두지 않는다).
- **타사 견적에서 대안을 적용한 계획**(기획서 4.1.2 7~8단계)은 `mode=upgrade` 로 만들어지지만 사용자가 나머지 부품을
  아직 갖고 있지 않다. 이 경우는 업그레이드가 아니라 새 PC 조립으로 안내한다(G8, 4.2).

## 4. 제안

### 4.1 단계 구조 — 새 PC

조립 관행대로 **보드를 케이스 밖에서 먼저 조립**하는 순서로 바꾼다(G1). 단계는 부품 단위가 아니라 작업 단위다.

| 단계 | 내용 | 붙는 조합 확인(검사 axis) |
|---|---|---|
| 0. 준비 | 공구(+ 드라이버), 정전기 방전, 박스 위 작업 공간 | — |
| 1. 보드 밖 조립 | CPU → RAM → M.2 SSD → 쿨러(브래킷·백플레이트, 서멀) | `socket`, `cooler_socket`, `ram_slots`(모듈 2개 → 슬롯 A2/B2), `m2`(슬롯 수·세대), `memory` |
| 2. 케이스 준비 | 옆판 열기, 스탠드오프 위치, I/O 실드 | `motherboard_case` |
| 3. 파워 장착 | 팬 방향, 나사 4개, 케이블 미리 빼 두기 | `psu_form`, `psu_length` |
| 4. 보드 장착·배선 | 스탠드오프에 보드 고정, 24핀·CPU 보조전원·프론트 패널·팬 | `cooler_height`(옆판 닫힘), `radiator` |
| 5. 그래픽카드 | 확장 슬롯 덮개, 슬롯 잠금, 전원 케이블 | `gpu_len`(여유 mm), `gpu_slots`, `gpu_connector`(어댑터 필요 여부), `power` |
| 6. 첫 부팅 점검 | BIOS에서 CPU·RAM 용량·SSD 인식, XMP/EXPO(CPU 제조사로 이름 결정), 드라이버, 온도 | `ram_speed`, `bios` |

단계 안의 줄은 세 종류다.

- **설치** — 설치 문서(kind=install). 지금 있는 8건을 작업 단위로 다시 나누고 모자란 것을 채운다(4.4).
- **이 조합** — 해당 axis의 검사 결과 문장. 코드가 만든다. 예:
  - ok: "GPU 길이 305mm, 케이스 허용 400mm — 95mm 여유가 있습니다."
  - unknown: "GPU 두께 데이터가 없어 확장 슬롯 칸 수를 확인하지 못했습니다. 설명서의 '슬롯 두께' 항목을 확인하세요."
  - 어댑터: "파워에 16핀 케이블이 없어 GPU에 동봉된 어댑터로 연결해야 합니다."
  - fail이 남은 채 확정됐으면 "확정 전 호환 검사에서 맞지 않는 것으로 나왔습니다"로 그대로 낸다.
- **주의** — care 문서 중 **조립 시점 문서만**(4.4의 `phase`). 구매 전 문구는 싣지 않는다(G2).

### 4.2 단계 구조 — 업그레이드

교체하는 부품마다 "선행 → 분리 → 장착 → 확인"을 만든다. 유지하는 부품과의 호환 결과를 같이 싣는다
(업그레이드 결과 화면이 이미 유지 부품을 `owned_for_conditions` 로 넣어 검사한다).

| 교체 부품 | 선행(교체 전에) | 확인(교체 뒤) |
|---|---|---|
| CPU | **기존 CPU로 BIOS를 새 CPU 지원 버전으로 먼저 업데이트**(`bios` 결과가 "출고 BIOS 버전은 확인하지 않음"이면 반드시 표시) | BIOS에서 새 CPU 이름 확인 |
| GPU | 기존 그래픽 드라이버 정리 | 새 드라이버 설치, 전원 커넥터 |
| RAM | — | XMP/EXPO 다시 켜기(교체하면 꺼진다) |
| 저장장치 | 기존 디스크 백업, 운영체제를 옮길지(복제) 새로 설치할지 | 디스크 초기화·인식 |
| 파워 | 기존 파워 케이블을 새 파워에 쓰지 않기(모듈러 케이블은 제조사마다 핀 배열이 다르다) | — |
| 메인보드 | 사실상 재조립 — 새 PC 순서(4.1)를 쓴다 | — |

여러 부품을 바꾸면 선행을 모아서 앞에 낸다(예: CPU+GPU → BIOS 업데이트 → 드라이버 정리 → 분리 → 장착).

**타사 견적에서 온 계획(G8)은 4.1 새 PC 순서를 쓴다.** 구매 품목에 더해 견적의 나머지 부품(`current_specs`, 카탈로그에
매칭된 경우 그 제품)을 단계에 넣고, 나머지 부품 줄에는 "받은 견적의 부품 — 따로 구매" 표시를 붙인다. 분리·선행 단계는
만들지 않는다. 이를 위해 계획에 출처 표시가 필요하다(6절 5번).

### 4.3 데이터 흐름

```
get_report
  └ 확정 스냅샷 품목(본체 슬롯만) + 확정 revision 의 조건(mode, current_specs, 출처 표시)
      ├ 본체 품목 0건 → 가이드 섹션 없음
      ├ 출처 = 타사 견적 → 새 PC 순서(4.1), 나머지 부품 포함
      └ recommendation_service.compat_checks(...)  ← 결과 화면과 같은 호환 검사, 저장 안 함
          └ assembly_guide.build(mode, items, compat_rows)
              ├ 단계 뼈대: 코드(4.1 / 4.2 표)
              ├ 설치·주의: search_care_guide(slot, kind, phase)
              └ 이 조합: compat_rows → axis 별 문장 템플릿
```

- 응답 모양은 **지금 문자열 형식을 유지**한다(`번호. 제목` / `설치: …` / `확인: …`). 화면 파서가 이 형식을 읽는다.
  새 줄 종류 `이 조합:` · `주의:` 는 파서 정규식에 두 단어만 더하면 된다(프론트 한 줄 변경, 프론트 담당 확인).
- 구조화 JSON(steps 배열)으로 바꾸는 것은 API 계약 변경이라 9/30 이후로 미룬다. 단 리포트 화면이 재기획
  대상(기획서 UI-11)이라, 새 화면이 단계 구조를 요구하면 9/30 안에 앞당길 수 있다(6절 2번).
- `이 조합` 줄은 검사 axis 별로 한 줄이다. 기획서 ENG-06(검사 결과에 제조사 문서 근거, P2)이 들어오면 같은 axis 줄
  끝에 출처만 붙인다. 가이드가 검사 결과를 따로 해석하지 않으므로 ENG-06 쪽 변경에 끌려가지 않는다.

### 4.4 문서 데이터

| 작업 | 내용 |
|---|---|
| care 문서에 `phase` 추가 | `purchase`(구매 전) / `assembly`(조립 중) / `after`(조립 뒤). 결과 화면 "구매 전 확인"은 지금처럼 전부, 조립 가이드는 `assembly`·`after` 만 |
| install 문서 재구성 | 부품 단위 8건 → 작업 단위: 보드 밖 조립, 스탠드오프·I/O 실드, 프론트 패널 배선, 첫 부팅 점검, XMP/EXPO |
| 업그레이드 문서 | 부품별 분리 방법 6건, CPU 교체 전 BIOS 업데이트, 드라이버 정리, 디스크 복제 |
| 검수 | 모두 합성 문서다. 팀 검수 전에는 리포트에 "일반 조립 상식으로 작성한 안내" 문구를 유지한다 |

실제 제조사 매뉴얼 검색은 RAG 고도화(RAG-01, P1)의 몫이다. 이 기획은 매뉴얼이 들어오면 `설치` 줄의 출처만 바뀌게 짠다.

### 4.5 LLM의 자리

- **리포트 본문은 규칙으로 만든다.** 인쇄할 때마다 같은 문장이 나와야 하고, 수치는 계산값이어야 한다(G7).
- LLM은 **채팅에서 가이드를 묻는 경우**에 쓴다 — "파워 케이블은 어디에 꽂아?" 같은 질문에 이 가이드와 설치 문서만 근거로
  답한다(되묻기 에이전트와 같은 가드: 입력에 없는 숫자 금지). 9/30 범위에서는 선택 항목이다.
- 지금 LLM 경로(`available()` 분기)는 걷어내거나, 켜더라도 확정 시점에 한 번 만들어 저장하는 쪽을 제안한다(6절).
