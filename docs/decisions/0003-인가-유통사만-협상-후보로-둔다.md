# 0003. 인가 유통사만 협상 후보로 둔다 (기본값)

- 날짜: 2026-09-05
- 상태: 결정됨
- 관련: [0002](0002-스냅샷은-원본을-보존하고-해석은-읽는-시점에.md),
  `app/snapshot_catalog.py` (`SNAPSHOT_AUTHORIZED_ONLY`)

## 맥락

실데이터를 받아보니 한 부품에 판매자가 최대 52곳까지 붙었다. 28품목 전체로는
96곳이다. 그런데 두 무리로 뚜렷하게 갈렸다.

`STM32F103C8T6` 한 부품의 최저가 분포:

| | 곳 | 최저가 | 예 |
|---|---|---|---|
| `isAuthorized` | 9 | 3,612 ~ 7,453원 | Arrow, Mouser, DigiKey, Newark, Avnet, TME |
| 비인가 | 43 | 258 ~ 1,095원 | GreenTree(IL), Fmall·TIST(HK), Epart123(CN) |

28품목 전체에서 **비인가 최저가가 인가 최저가의 1/4.4(중앙값)** 이다. 극단은 설명이 안 된다.

| 품목 | 인가 최저 | 비인가 최저 |
|---|---|---|
| `DP83867IRPAPR` (기가비트 이더넷 PHY) | 4,033원 | **37원** |
| `IPP041N12N3G` (파워 MOSFET) | 2,459원 | **13원** |
| `IHLP2525CZER100M01` (파워 인덕터) | 422원 | **13원** |

기가비트 PHY가 37원일 수는 없다. 같은 물건이 아니거나 회색시장 호가다.

거르지 않으면 협상이 매번 그쪽을 고른다. 시연 자리에서 "왜 이 업체가 이겼나"에
답할 수 없고, 이 프로젝트가 보여주려는 것(근거가 남는 자동 협상)과 정반대가 된다.

`isBroker` 로는 못 거른다 — 이 데이터에서 **전부 `false`** 다. `isAuthorized` 가
유일한 판별 기준이다.

## 결정

`SNAPSHOT_AUTHORIZED_ONLY` 를 두고 **기본값을 켜둔다.**

거르는 자리는 조회가 아니라 **로더**다(ADR 0002). 스냅샷 파일에는 96곳이 전부
남아 있고, 환경변수를 `false` 로 두면 즉시 되돌아온다.

```
켬(기본)  220행 · 판매자 33곳 · 품목 28개
끔       1,039행 · 판매자 96곳 · 품목 28개
```

## 왜 이 기본값이 안전한가

**걸러도 완료 기준이 유지된다.** 28품목 전부 인가 유통사가 3곳 이상 남는다.
"같은 품목에 판매자가 2곳 이상이라 협상 후보가 실제로 생긴다"는 기준이 필터와
양립한다는 것을 확인하고 기본값으로 정했다.

## 대가

- **가장 싼 값을 버린다.** 실제 조달에서 비인가 유통사는 정당한 선택지다.
  급하거나 단종된 부품은 거기밖에 없다. 이 시스템은 그 판단을 못 한다
- **한 축을 통째로 감춘다.** "정품 프리미엄이 얼마인가"는 그 자체로 협상 소재인데
  기본 화면에서 사라진다
- **기준이 API 한 필드에 달려 있다.** `isAuthorized` 가 틀리거나 정책이 바뀌면
  우리 판단도 같이 틀어진다. 검증할 수단이 없다

## 검토했다가 안 간 길

- **거르지 않고 다 보여주기** — 협상이 항상 13원짜리를 고른다
- **가격 이상치로 거르기** (예: 중앙값의 1/3 미만 제외) — 임계값을 우리가 지어내야
  하고, 정당한 저가 유통사까지 걸린다. `isAuthorized` 는 적어도 API가 주는 사실이다
- **조회 단계에서 `requireAuthorizedSellers`** — 파일이 작아지지만 원본이 손상된다.
  끄고 비교하는 것 자체가 불가능해진다
