## 맥락

[`0008`](0008-리뷰-소스-기본값을-합성으로-둔다.md) 이 리뷰 소스를 합성으로 두면서
숙제를 하나 남겼다 — *"실데이터에는 라벨이 없다. 파이프라인이 끝까지 도는 것을
보고 3단계가 됐다고 착각하기 쉽다."* 그 착각을 깨려면 실 리뷰가 붙어야 한다.

부품 마스터 322행(8개 부품군)이 손으로 채워져 도착했다. 이 목록의 제품에 붙는
리뷰를 모아 클렌징해서 쓰는 것이 이 문서의 결정이다.

**어디서 가져올 수 있는지부터 실측했다(2026-09-09).**

| 소스 | 결과 |
|---|---|
| 네이버 | 리뷰 API 없음(0008에서 이미 확인). 데이터랩·쇼핑인사이트는 검색 트렌드만 |
| 쿠팡 | `robots.txt` 조차 403. 자동 수집 경로가 없다 |
| Reddit | 비로그인 차단. 공식 API 등록이 선행 |
| 아마존 리뷰 2023 공개 데이터셋 | 존재하고 대량이나 **영어**이고 국내 유통 제품과 매칭이 안 된다 |
| 다나와 | `robots.txt` 가 상품 페이지를 막지 않는다. `Crawl-delay: 10` |
| 에누리 | 마찬가지로 열려 있다 |

**다나와에 얼마나 있는지도 쟀다.** 부품군별 대표 제품 10개:

| 제품 | 다나와 의견 | 몰 리뷰 |
|---|---|---|
| 써멀라이트 Peerless Assassin 120 | 563 (의견 56 · 질문 491 · 후기 16) | 129 |
| 삼성 DDR5-5600 32GB | 240 | 122 |
| 삼성 990 PRO 2TB | 223 | 385 |
| ASRock B650M Pro RS | 196 | 35 |
| 시소닉 FOCUS GX-850 | 112 | 22 |
| MSI RTX 5070 Ti 게이밍 트리오 | 73 | 50 |
| 앱코 SUITMASTER | 17 | 4 |
| 이엠텍 RTX 5060 Ti | 3 | 1 |

`verify.py` 의 `MIN_RELEVANT` 가 **주장에 닿는** 리뷰 10건이다. 특정 주장을
언급하는 비율을 10% 안팎으로 보면 **제품당 100~300건**이 있어야 판정이 나온다.
인기 부품은 넘고 신제품·틈새는 한참 못 미친다.

## 결정

**다나와를 첫 실소스로 붙이되, 원문은 저장소에 넣지 않는다.**

**1. `REVIEW_SOURCE=collected` 를 추가하고 기본값은 그대로 `synthetic` 이다.**
`CATALOG_SOURCE=snapshot` 처럼 아무것도 설정하지 않아도 도는 성질을 깨지 않는다.
실 리뷰는 모은 사람의 기계에서만 돈다.

**2. 원문은 로컬에만, 저장소에는 파생 지표만.**

    data/reviews_raw/        수집 원문        .gitignore 로 막힘
    data/reviews_clean/      엔진이 읽는 문장  .gitignore 로 막힘
    data/reviews_snapshot.json  건수·분포·출처  **이것만 커밋**

2026-09-08 방침(리뷰 원문을 그대로 저장·노출하지 않는다)과 데모 재현성 사이의
타협점이다. 스냅샷만으로 *"어느 상품에서 몇 건을 모아 몇 건을 왜 버렸는가"* 를
검증할 수 있고, 원문을 보려면 다시 모아야 한다.

**3. 개인정보는 파싱하는 자리에서 버린다.** 다나와 의견에는 닉네임과 부분
마스킹된 IP(`112.xxx.56.193`)가 함께 온다. 지우는 단계를 뒤에 두면 그 사이 파일에는
남는다. IP 는 아예 받아 적지 않고, 닉네임은 소금친 해시만 남긴다 — 조작 신호로
필요한 것은 *"같은 사람인가"* 뿐이고 *"누구인가"* 는 필요 없다.

**4. 어느 상품에 붙일지를 네 겹으로 거른다.** 실사에서 드러난 실패가 전부 여기서
났다. `Core i5-13400F` 를 검색하면 **1위가 그 CPU 를 넣은 완제품 PC** 다
(`영웅컴퓨터 영웅 RL3461F i5-13400F RTX5060Ti`). 이름만 보면 100% 일치한다.

    분류 코드   완제품(112756 · 11316681)을 여기서 자른다. 가장 강한 필터
    제외어      중고·번들·액세서리
    모델 꼬리표  `RTX 5070` 이 `RTX 5070 Ti` 에 붙는 것을 막는다
    낱말        `Peerless Assassin 120` 과 `Assassin X 120` 을 가른다

**5. 리뷰를 문장으로 쪼개지 않는다.** 짧을수록 대조가 선명하지만, `MIN_RELEVANT`
와 `REFUTE_RATIO` 는 **건수**에 대한 값이다. 한 리뷰를 다섯 문장으로 쪼개면 한
사람의 의견이 다섯 표본이 되어 판정이 바뀐다.

**6. 조작 확률을 클렌징이 매기지 않는다.** 신호(`risk_signals`)만 붙이고 점수는
`None` 으로 둔다. 0.0 으로 채우면 *"조작 확률 20% 이상을 걸렀다"* 는 화면의 약속이
에러 없이 무력해진다.

**7. 요청 간격은 상대가 적어 둔 값을 따른다.** `search.danawa.com` 이
`Crawl-delay: 10` 을 적어 뒀으므로 검색은 10초에 한 번이다. 연속 실패 3회면
백오프가 아니라 **중단**한다 — 실패가 이어지는 것은 대개 차단됐다는 뜻이고, 그때
재시도를 계속하면 차단이 넓어진다(2026-09-09 회의에서 나온 걱정이 정확히 이것이다).

## 실 리뷰로 3단계를 돌려 본 결과 (2026-09-09)

CPU 두 품목(각 45·51건)에 `MATCH_MODE=llm` 으로 주장 넷을 대조했다.

| 품목 | 주장 | 닿음 | 어긋남 | 판정 |
|---|---|---|---|---|
| i5-12400F | 가격 대비 성능이 좋다 | 18 | 4 (.222) | **✕ 반증** |
| i5-12400F | 기본 쿨러로 정격 온도가 유지된다 | 3 | 0 | · 근거 없음 |
| i5-14600K | 기본 쿨러로 정격 온도가 유지된다 | 7 | 0 | · 근거 없음 |
| i5-14600K | 발열이 낮다 | 5 | 1 | · 근거 없음 |

**돌긴 돈다.** 라벨 없는 실 리뷰에서 의미 대조가 판정 하나를 냈다 — `0008` 이
"공짜였다"고 적은 그 판단을 모델이 실제로 했다. 그리고 세 가지가 같이 드러났다.

1. **표본이 얇다.** 50건으로는 넓은 주장만 임계값을 넘는다. 기술적인 주장일수록
   닿는 리뷰가 3~7건이라 계속 "근거 없음"이다. 품목당 100건이 아니라 **300건**을
   받아야 하는 이유가 이 표다
2. **지어낸 인용이 실제로 나온다.** `match.accept` 가 *"원문에 없는 인용을
   지웁니다"* 를 네 번 찍었다. 합성 데이터에서는 잘 안 보이던 가드레일이
   실데이터에서 매번 일한다
3. **조작 확률이 전부 미측정이다.** `unscored_risk` 가 표본 전체(45·51)라
   화면 고지가 "20% 이상을 걸렀다"가 아니라 "거르지 못한 것이 섞여 있다"가 된다

## 대가

- **이용약관 판단이 남아 있다.** `robots.txt` 가 막지 않는다는 것은 확인했지만
  그것과 이용약관은 다른 문서다. 원문을 재배포하지 않고, 저장소에 넣지 않고,
  요청을 느리게 하는 것으로 위험을 **줄였을 뿐** 없앤 것이 아니다. 상업적
  운영으로 넘어갈 때 다시 판단해야 한다
- **다른 사람 기계에서는 `collected` 가 안 돈다.** 원문이 커밋되지 않으므로
  각자 모아야 한다. 검사와 데모의 기본값이 `synthetic` 인 이유이기도 하다
- **칩 단위 주장에 카드 단위 리뷰가 붙는다.** 부품 마스터의 GPU 는 칩
  (`GeForce RTX 5070 Ti`)인데 리뷰는 특정 AIB 카드(MSI 게이밍 트리오)에 달린다.
  온도·소음 주장은 카드마다 다르므로, 지금 판정은 *"그 칩의 대표 카드 하나"* 에
  대한 것이다. 여러 카드를 합치면 표본은 늘지만 카드별 차이가 뭉개진다
- **임계값 재보정이 남았다.** `MIN_RELEVANT=10` 은 합성 분포에서 나온 값이고,
  실측 분포에서는 저인기 부품이 계속 "근거 없음"으로 끝난다. 이게 나쁜 결과는
  아니지만(모르는 것을 모른다고 말한다), 데모에서 그 화면만 보이면 3단계가
  아무것도 안 하는 것처럼 보인다
- **조작 확률이 아직 전부 미측정이다.** `unscored_risk` 가 표본 전체가 되므로
  *"조작 확률 20% 이상 62건 제외"* 같은 목업 문구를 실데이터에서는 아직 쓸 수 없다.
  `RISK_MODE=llm` 을 켜야 채워진다
- **수집이 느리다.** `Crawl-delay: 10` 때문에 322행 실사에 약 한 시간이다.
  부품이 늘면 선형으로 는다

## 검토했다가 안 간 길

- **쿠팡.** `robots.txt` 요청부터 403 이다. 파트너스 오픈API 는 제휴 링크용이라
  리뷰가 없다(2026-09-08 회의에서 이미 확인)
- **네이버.** 리뷰 API 가 없다는 결론이 0008 에서 두 경로로 확인됐다. 데이터랩·
  쇼핑인사이트는 검색 트렌드만 준다
- **아마존 리뷰 2023 공개 데이터셋.** 라이선스가 명확하고 양이 압도적이지만
  영어이고, 국내 유통 제품명과 매칭이 거의 안 된다. 케이스·파워 같은 국내
  브랜드는 아예 없다
- **요청 시점에만 가져오고 저장하지 않기**(2026-09-09 회의에서 나온 RAG 방향).
  방침에는 가장 충실하지만 데모 중 응답이 수십 초로 늘고, 발표가 외부 사이트
  상태에 걸린다. 지금 구조는 그 방향과 배타적이지 않다 — 수집기를 요청 경로에서
  부르면 되고, 캐시가 `reviews_clean/` 이다
- **에누리를 둘째 소스로 붙이기.** `robots.txt` 는 열려 있는데 **상품평이 정적
  HTML 에 없다**(2026-09-09 확인 — 상세 페이지에 빈 컨테이너만 있고 내용은
  나중에 채워진다). 리뷰 API 를 따로 찾아내야 해서 이번에는 안 했다. 소스를
  더 붙이는 자리는 `scripts/collect_reviews.py` 의 `SOURCES` 한 줄이다.
  덧붙여, 다나와 수집에는 **쇼핑몰 상품리뷰**(G마켓·옥션 등)가 이미 함께 들어와서
  한 소스로도 여러 쇼핑몰의 리뷰가 섞여 들어온다
- **리뷰를 문장으로 쪼개 표본을 늘리기.** 표본 임계값이 건수 기준이라 판정이
  조용히 바뀐다. 위 결정 5
