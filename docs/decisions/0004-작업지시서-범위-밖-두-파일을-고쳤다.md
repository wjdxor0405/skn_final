# 0004. 작업지시서가 금지한 두 파일을 고쳤다

- 날짜: 2026-09-05
- 상태: 결정됨 — **병합 담당자가 읽어야 한다**
- 관련: `docs/카탈로그-스냅샷-작업지시.md` ("하지 말 것" 절),
  `app/negotiate.py`, `app/feasibility.py`, `tests/test_snapshot_catalog.py`

## 맥락

작업지시서는 Strands 이식 담당이 동시에 고치는 파일을 지목하고 손대지 말라고 했다
(`llm_agents.py` · `negotiate.py` · `agents.py` · `audit.py`). `feasibility.py` 는
금지 목록에도 변경 지점에도 없지만, 지시서 함정 5는 "BOM 전개는 계속 Odoo 담당"
이라고 적었다.

이 경계를 지키면 스냅샷 모드에 구멍이 둘 남는다.

1. **수량구간이 죽는다.** `negotiate.py:51` 이 `sellers_for(request.item)` 로
   불러서 수량을 안 넘긴다. 스냅샷은 수량구간을 전부 갖고 있고 로더도
   `sellers_for(item, qty)` 로 지원하는데, 호출부에서 끊겨 있었다.
   28품목 중 22품목에서 수량에 따라 최저가 유통사가 바뀌는데 그게 안 보인다
2. **납품 가능성 검증이 터진다.** `feasibility.check` 가 `CATALOG_SOURCE` 와
   무관하게 Odoo를 세 군데서 읽어서 `/api/feasibility` 가 500으로 떨어진다

저장소 주인이 둘 다 고치라고 명시적으로 요청했다.

## 결정

**고치되, 병합에서 조용히 되돌아가지 않게 한다.**

- `negotiate.py` 는 **한 줄**만 바꾼다 — `sellers_for(request.item, request.qty)`.
  3-way merge 로 풀리게 두는 것이 목적이다
- `feasibility.py` 는 Odoo 호출을 헬퍼 둘(`_product_and_bom` · `_vendor_offers`)로
  모으고 거기서만 출처를 가른다. Odoo 경로의 동작은 그대로다
- **두 변경 다 회귀 검사를 붙인다.** 되돌아가도 에러가 안 나고 조용히 옛 동작으로
  돌아가기 때문이다. 이게 이 결정의 핵심이다

| 검사 | 되돌아가면 |
|---|---|
| `negotiation_qty` | 1개·500개 요청의 낙찰자가 같아진다 → 실패 |
| `feasibility` | Odoo 없이 도는 검사라 무조건 호출로 돌아가면 → 실패 |

## 병합할 때

`negotiate.py:51` 은 **의도적으로 지시서 범위 밖**이다. 충돌이 나면 인자를 살리는
쪽으로 풀어야 한다. `python tests/test_snapshot_catalog.py` 로 확인된다.

## 붙이면서 발견한 것 (이 결정과 별개로 중요)

`feasibility.py` 가 **이 모듈이 막으려던 답을 스스로 내고 있었다.** 판매자 재고를
보지 않아서 커넥터 50만 개도 "가능"이라고 답했다. Odoo 모드는 공급능력을
무제한으로 가정하니(`ODOO_VENDOR_CAPACITY`) 드러나지 않던 구멍인데, 스냅샷에는
실재고가 있다. 검증이 통과시킨 물량을 협상 스크리닝이 전원 탈락시키면 두 판정이
어긋난다.

조달 후보를 그 수량을 실제로 댈 수 있는 곳으로 좁히고 `max_feasible_qty` 도 공급
한도로 잘랐다. 자르기 전에는 이렇게 답했다:

```
· 838,293개를 댈 수 있는 판매자가 없습니다 (한 곳의 최대 보유량 694,443개).
· → 납기 내 최대 838,293개까지 가능합니다.     ← 앞줄과 모순
```

`supply_qty=None`(공급능력을 모르는 출처)이면 제약이 적용되지 않아 Odoo 동작은 불변이다.

## 대가

- **병렬 작업자와 충돌할 수 있다.** 한 줄로 줄이고 테스트를 붙여 완화했을 뿐
  없앤 게 아니다
- **`feasibility.py` 가 카탈로그 출처를 알게 됐다.** "출처를 모르는 상위 모듈"이라는
  기존 설계 원칙이 이 파일에서는 깨졌다. `store.py` 처럼 출처를 흡수하는 자리로
  옮기는 게 옳지만, 지금은 범위를 더 넓히지 않는 쪽을 택했다
